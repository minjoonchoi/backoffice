# Backoffice UI 기능 요구사항

## 1. 문서 정보

| 항목          | 내용                                                                                 |
| ------------- | ------------------------------------------------------------------------------------ |
| 문서 목적     | 백오피스 메뉴별 화면 구성, 사용자 흐름, 상호작용, 접근성 및 UI 완료 조건을 정의한다. |
| 대상 사용자   | 백오피스 운영자, 기획자, 디자이너, 프런트엔드 개발자, QA 담당자                      |
| 기준일        | 2026-08-18                                                                           |
| 서버 요구사항 | [Backoffice 서버 기능 요구사항](server-functional-requirements.md)                   |
| MVP 이후 범위 | [Backoffice MVP 이후 UI 기능 요구사항](post-mvp-ui-functional-requirements.md)       |

이 문서는 UI 기능과 동작의 원본이다. 데이터 무결성, 권한 재검증, 상태 전이, 영속 저장, 감사 로그와 외부 시스템 연동은 서버 요구사항 문서에서 관리한다. 화면 입력 제약은 사용자 피드백을 위해 서버 규칙을 반영하지만 업무 규칙의 최종 판정은 서버가 담당한다.

현재 MVP 화면에서 제외하기로 확정한 기능은 이 문서에 중복해서 두지 않고 MVP 이후 UI 기능 요구사항 문서에서 관리한다. 구현된 컴포넌트와 도메인 로직은 재사용을 위해 유지할 수 있지만 MVP 화면의 진입점과 표시 영역에서는 노출하지 않는다.

요구사항 상태는 다음과 같이 구분한다.

- `구현`: 현재 프런트엔드 워크스페이스에서 확인할 수 있다.
- `후속`: UI 기능 요구사항은 확정되었으나 아직 화면에서 확인할 수 없다.

요구사항 ID는 기존 추적성을 위해 유지한다. 번호가 연속되지 않는 경우 해당 규칙이 서버 문서로 이동한 것이다.

### 13.2 자격증명 요청 UI 흐름

1. 입력 단계에서 서비스를 검색하고, 내부 서비스라면 자격증명을 사용할 엔드포인트를 복수 선택한다. 서비스와 엔드포인트 목록은 데스크톱에서 나란히 배치하고 각각 충분한 스크롤 높이를 제공한다.
2. 같은 입력 단계에서 자격증명 이름, AWS ASM Secret name, Secret value key, 자동 선택된 요청 조직, 사용자 정의 필드와 요청 사유를 작성한다. 외부 서비스는 엔드포인트 선택 없이 서비스 범위로 요청한다.
3. 검토 단계에서 서비스, 선택 엔드포인트와 입력 정보, Groo 결재 위임을 확인한다. 자격증명 발급 요청에서는 내부 결재선을 표시하거나 편집하지 않는다.
4. 제출에 성공하면 Groo가 발급한 고유 요청 ID가 매핑된 요청 상세로 이동한다.
5. Groo 완료 hook 수신 전에는 승인 대기로 표시하고 승인 결과를 수신한 요청은 등록 대기로, 반려 결과를 수신한 요청은 반려로 표시한다.
6. 등록 대기 요청은 권한이 있는 사용자에게만 등록 버튼을 제공한다. 내부 서비스는 시스템 등록 확인 Dialog, 외부 서비스는 원문 수동 입력 Dialog를 제공한다.
7. 활성 API Key 상세에서 시작하는 교체·폐기 요청은 내부 결재선의 후속 단계를 요청별로 조정하고 전체 요청 이력을 표시한다.

서버 처리 순서와 실패 조건은 `KEY-S002~KEY-S007`을 따른다.

## 17. UI 범위에서 제외하는 기능

- 모바일 전용 내비게이션과 모바일 전용 업무 컴포넌트
- 브랜드 로고, 브랜드 전용 색상과 다크 모드
- 실제 인증 공급자 로그인 화면
- API Key 원문 재조회 또는 클라이언트 저장
- 서버 페이지네이션이 연결되기 전의 원격 검색 상태 UI
- 운영 인증 공급자 및 장기 실행 workflow와 연결된 실제 승인 처리

## 18. UI 인수 기준

- 입력 오류와 서버 오류를 구분해 사용자가 수정할 수 있는 위치에 표시해야 한다.
- 권한 없는 메뉴·view·action을 노출하지 않고 직접 URL에는 403 상태를 제공해야 한다.
- 관계 추가·제거 결과는 연결된 양쪽 상세 화면에 일관되게 표시해야 한다.
- 일반 텍스트는 WCAG AA 4.5:1, UI와 focus indicator는 3:1 이상의 대비를 유지해야 한다.
- 주요 Dialog와 선택 흐름은 키보드만으로 완료할 수 있어야 한다.
- 한국어와 영어의 선택 옵션과 선택값이 같은 언어로 표시되고 긴 문자열이 레이아웃을 깨뜨리지 않아야 한다.
- 320px과 데스크톱 viewport에서 작업 페이지, Dialog, popup과 테이블이 viewport를 벗어나지 않아야 한다.
- Chromium, Firefox와 WebKit에서 핵심 UI 흐름이 동일하게 동작해야 한다.
