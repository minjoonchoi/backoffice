# Backoffice UI 기능 요구사항

## 1. 문서 정보

| 항목          | 내용                                                                                 |
| ------------- | ------------------------------------------------------------------------------------ |
| 문서 목적     | 백오피스 메뉴별 화면 구성, 사용자 흐름, 상호작용, 접근성 및 UI 완료 조건을 정의한다. |
| 대상 사용자   | 백오피스 운영자, 기획자, 디자이너, 프런트엔드 개발자, QA 담당자                      |
| 기준일        | 2026-08-12                                                                           |
| 서버 요구사항 | [Backoffice 서버 기능 요구사항](server-functional-requirements.md)                   |

이 문서는 UI 기능과 동작의 원본이다. 데이터 무결성, 권한 재검증, 상태 전이, 영속 저장, 감사 로그와 외부 시스템 연동은 서버 요구사항 문서에서 관리한다. 화면 입력 제약은 사용자 피드백을 위해 서버 규칙을 반영하지만 업무 규칙의 최종 판정은 서버가 담당한다.

요구사항 상태는 다음과 같이 구분한다.

- `구현`: 현재 프런트엔드 워크스페이스에서 확인할 수 있다.
- `후속`: UI 기능 요구사항은 확정되었으나 아직 화면에서 확인할 수 없다.

요구사항 ID는 기존 추적성을 위해 유지한다. 번호가 연속되지 않는 경우 해당 규칙이 서버 문서로 이동한 것이다.

## 2. 전체 메뉴 구조

| 영역            | 메뉴         | FE 고정 라우트                                                                                      |
| --------------- | ------------ | --------------------------------------------------------------------------------------------------- |
| 공통            | 홈           | `/`                                                                                                 |
| IAM             | 사용자       | `/users`, `/users/{userId}`                                                                         |
| IAM             | 조직         | `/organizations`, `/organizations/{organizationId}`                                                 |
| IAM             | 역할         | `/roles`, `/roles/{roleId}`                                                                         |
| IAM             | 그룹         | `/groups`, `/groups/{groupId}`                                                                      |
| 공통            | 정책         | `/approval-documents`, `/approval-documents/{policyId}`, `/approval-documents/requests/{requestId}` |
| 공통            | 자격증명     | `/api-keys`, `/api-keys/{apiKeyId}`                                                                 |
| 서비스 카탈로그 | 서비스       | `/services`, `/services/{serviceId}`                                                                |
| 서비스 카탈로그 | 엔드포인트   | `/service-endpoints`, `/service-endpoints/{endpointId}`                                             |
| UI 카탈로그     | 네임스페이스 | `/namespaces`                                                                                       |
| UI 카탈로그     | UI 리소스    | `/ui-resources`                                                                                     |
| 시스템 관리     | 요청 템플릿  | `/approval-lines`, `/approval-lines/{approvalLineId}`                                               |

라우트와 메뉴 영역은 프런트엔드 코드 레지스트리에서 관리한다. 권한 데이터는 경로가 아닌 안정적인 UI 리소스 식별자를 사용한다. 서버 저장 및 판정 규칙은 `COM-S003`, `COM-S009`를 따른다.

### 13.2 자격증명 요청 UI 흐름

1. 사용자는 대상 선택 단계에서 서비스를 검색하고, 내부 서비스라면 자격증명을 사용할 엔드포인트를 복수 선택한다. 서비스와 엔드포인트 목록은 데스크톱에서 나란히 배치하고 각각 충분한 스크롤 높이를 제공한다.
2. 외부 서비스는 엔드포인트 선택 없이 서비스 범위로 요청한다.
3. 요청 정보 단계에서 자격증명 이름, AWS ASM Secret name, Secret value key, 자동 선택된 요청 조직, 사용자 정의 필드와 요청 사유를 입력한다.
4. 요청 전 검토 단계에서 서비스, 선택 엔드포인트, 입력 정보와 결재선을 확인하고 필요한 동적 처리 담당자를 지정한 뒤 제출한다.
5. 승인 완료 요청은 등록 대기로 표시하고 권한이 있는 사용자에게만 등록 버튼을 제공한다.
6. 내부 서비스는 시스템 등록 확인 Dialog, 외부 서비스는 원문 수동 입력 Dialog를 제공한다.
7. 활성 API Key 상세에서 교체·폐기 요청을 시작하고 전체 요청 이력을 표시한다.

서버 처리 순서와 실패 조건은 `KEY-S002~KEY-S007`을 따른다.

## 15. UI 범위에서 제외하는 기능

- 모바일 전용 내비게이션과 모바일 전용 업무 컴포넌트
- 브랜드 로고, 브랜드 전용 색상과 다크 모드
- 실제 인증 공급자 로그인 화면
- API Key 원문 재조회 또는 클라이언트 저장
- 서버 페이지네이션이 연결되기 전의 원격 검색 상태 UI
- 결재 단계별 실제 승인자 인증, 반려, 회수와 재상신 UI

## 16. UI 인수 기준

- 입력 오류와 서버 오류를 구분해 사용자가 수정할 수 있는 위치에 표시해야 한다.
- 권한 없는 메뉴·view·action을 노출하지 않고 직접 URL에는 403 상태를 제공해야 한다.
- 관계 추가·제거 결과는 연결된 양쪽 상세 화면에 일관되게 표시해야 한다.
- 일반 텍스트는 WCAG AA 4.5:1, UI와 focus indicator는 3:1 이상의 대비를 유지해야 한다.
- 주요 Dialog와 선택 흐름은 키보드만으로 완료할 수 있어야 한다.
- 한국어와 영어의 선택 옵션과 선택값이 같은 언어로 표시되고 긴 문자열이 레이아웃을 깨뜨리지 않아야 한다.
- 320px과 데스크톱 viewport에서 Dialog, popup과 테이블이 viewport를 벗어나지 않아야 한다.
- Chromium, Firefox와 WebKit에서 핵심 UI 흐름이 동일하게 동작해야 한다.
