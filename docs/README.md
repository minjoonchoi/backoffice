## 요구사항 작성 원칙

- 브라우저 표현과 사용자의 조작 방식은 UI 기능 요구사항에 작성한다.
- 클라이언트를 우회해도 반드시 지켜야 하는 규칙은 서버 문서에 작성한다.
- UI와 서버에 모두 영향을 주면 하나의 요구사항에 섞지 않고 각각 작성한 뒤 `서버 참조`로 연결한다.
- 데이터 필드와 업무 제약의 원본은 서버 문서이며 UI 문서는 입력·표시 방식만 정의한다.
- URL과 컴포넌트 배치는 UI 문서에서, 안정적인 리소스 식별자와 권한 계산은 서버 문서에서 관리한다.
- 구현 상태는 UI의 `구현`과 서버의 `로컬 검증`을 구분한다. `로컬 검증`은 운영 서버 구현 완료를 의미하지 않는다.
- 요구사항 ID는 수정하더라도 재사용하지 않는다. 삭제 대신 상태 변경이나 대체 ID 링크를 사용한다.
- MVP 제외가 확정된 요구사항은 현재 요구사항 문서와 중복하지 않고 대응하는 MVP 이후 문서로 이동한다.

## 변경 확인 순서

1. 사용자 화면이나 흐름이 달라지는지 확인한다.
2. 데이터, 권한 또는 상태 규칙이 달라지는지 확인한다.
3. 양쪽이 달라지면 UI 기능 요구사항과 서버 요구사항을 각각 수정하고 상호 참조한다.
4. 관련 테스트와 인수 기준을 함께 갱신한다.
